Workflow Diagram — Semantic Search System

StaySense Phitsanulok ระบบสารสนเทศเพื่อการบริหารจัดการและค้นหาที่พักด้วยเทคนิคการค้นหาเชิงความหมาย

เอกสารนี้อธิบาย Workflow Diagram แบบภาพรวมของระบบ StaySense Phitsanulok ซึ่งพัฒนาโดยใช้ Vue.js/Vite (Front-end), Node.js/Express.js (Back-end), MySQL (ฐานข้อมูล) และ Python (Semantic Search) ครอบคลุมผู้ใช้งาน 3 กลุ่ม คือ ผู้เยี่ยมชม สมาชิก และผู้ดูแลระบบ — ไม่มีฟังก์ชันเจ้าของที่พักหรือการจองที่พักในระบบนี้

Guest — ผู้เยี่ยมชม Registered User — สมาชิก Administrator — ผู้ดูแลระบบ Auth / Validation Semantic Search Database Error Start / End

02

สัญลักษณ์ที่ใช้ Flowchart Notation

Terminatorจุดเริ่มต้น (Start) และจุดสิ้นสุด (End) ของกระบวนการ
Processขั้นตอนการประมวลผลทั่วไป เช่น Create User Account
Input / Outputการรับข้อมูลหรือแสดงผล เช่น Enter Natural-Language Query
Decisionจุดตัดสินใจ มีเงื่อนไข Yes/No กำกับทุกเส้นทางออก
Databaseฐานข้อมูล MySQL หรือข้อมูลเวกเตอร์ที่จัดเก็บถาวร
Subprocessกระบวนการย่อยของ Semantic Search เช่น Query Preprocessing

ความหมายของเส้นเชื่อม Connectors

— เส้นทึบลำดับการทำงานปกติ (Sequence Flow) ไหลจากขั้นตอนหนึ่งไปยังอีกขั้นตอนหนึ่งภายในระบบเดียวกัน
┄ เส้นประการเรียกใช้บริการระหว่างองค์ประกอบทางเทคนิค (ในกล่อง System Architecture) เช่น Back-end เรียกใช้ MySQL หรือ Python Service
YES / NOป้ายกำกับบนเส้นที่ออกจากสัญลักษณ์ Decision ทุกจุด เพื่อระบุเงื่อนไขอย่างชัดเจน
Guest / Adminป้ายกำกับทางเลือกเมนู (Multi-way Branch) เช่น ที่ออกจาก Select User Type หรือ Select Operation ไม่ใช่เงื่อนไข Yes/No เพราะเป็นจุดแยกเมนู ไม่ใช่จุดตรวจสอบเงื่อนไข
03

สีที่ใช้แบ่งกลุ่มการทำงาน Color Coding

ฟ้าอ่อนผู้เยี่ยมชม (Guest) — การค้นหาและดูรายละเอียดที่พักโดยไม่ต้องเข้าสู่ระบบ
เขียวอ่อนสมาชิก (Registered User) — รายการโปรด ประวัติการค้นหา การเปรียบเทียบ คำแนะนำ
ส้มอ่อนผู้ดูแลระบบ (Administrator) — การบริหารจัดการข้อมูลทุกประเภท
เหลืองการยืนยันตัวตนและตรวจสอบความถูกต้องของข้อมูล (Authentication / Validation)
ม่วงอ่อนกระบวนการค้นหาเชิงความหมาย (Semantic Search) ที่ประมวลผลด้วย Python
เทาฐานข้อมูล MySQL และข้อมูลเวกเตอร์ (Database)
แดงอ่อนข้อความแจ้งเตือนข้อผิดพลาดหรือข้อมูลไม่ถูกต้อง (Error / Invalid Data)
เขียวเข้มจุดเริ่มต้นและจุดสิ้นสุดของกระบวนการ (Start / End)

ผู้ใช้งานเข้าสู่เว็บไซต์ StaySense Phitsanulok ระบบให้เลือกประเภทผู้ใช้งาน 3 ทาง

Registered User / Administrator — ไปยังหน้าจอเข้าสู่ระบบร่วมกัน
02

กระบวนการค้นหาเชิงความหมาย Semantic Search Workflow

ใช้ร่วมกันทั้งผู้เยี่ยมชมและสมาชิก ผู้ใช้พิมพ์คำค้นหาภาษาธรรมชาติ พร้อมกำหนดเงื่อนไขเพิ่มเติมได้

Enter Query → Select Filters → Use Location (Optional) → Submit → Validate Input
NO ข้อมูลไม่ถูกต้อง → แสดงข้อความแจ้งเตือน → กลับไปแก้ไขคำค้นหา
YES ส่งเข้าสู่ Back-end API
Send to API → Query Preprocessing → Convert Query to Vector → Retrieve Accommodation Vectors → Calculate Semantic Similarity → Apply Filters → Rank Results → Return Results
NO ไม่พบผลลัพธ์ → "No Matching Accommodation Found" → แก้ไขคำค้นหาใหม่
YES Display Search Results

07

การบริหารจัดการข้อมูลที่พัก (CRUD) Manage Accommodation Data

Select Operation → Add / View / Edit / Delete-Unpublish

Add — กรอกข้อมูลที่พัก ห้องพัก สิ่งอำนวยความสะดวก รูปภาพ พิกัด สถานที่สำคัญ แหล่งข้อมูล → Information Valid?

NO Display Validation Message → แก้ไขข้อมูล
YES Save to MySQL → Prepare Text → Convert to Vector → Save Vector → Publish → Display Success

Edit — แก้ไขข้อมูล → Update MySQL Database → Searchable Information Changed?

YES อัปเดตเวกเตอร์การค้นหาใหม่
NO จบกระบวนการโดยไม่ต้องแปลงเวกเตอร์ใหม่

Delete / Unpublish — Confirm Action?

NO กลับไปหน้าบริหารจัดการที่พัก
YES เปลี่ยนสถานะหรือลบข้อมูล → อัปเดตฐานข้อมูล → ลบ/ปิดใช้งานเวกเตอร์การค้นหา
แนะนำให้ใช้สถานะ "Unpublished / Inactive" แทนการลบถาวร เพื่อป้องกันข้อมูลสูญหายและรองรับการตรวจสอบย้อนหลัง

09

สถาปัตยกรรมทางเทคนิค System Architecture

แสดงแยกไว้ต่างหากในแผนภาพเพื่อไม่ให้เส้นเชื่อมยาวพาดผ่านผังหลักจนอ่านยาก โดยสอดคล้องกับขั้นตอนในผังหลักดังนี้

องค์ประกอบสอดคล้องกับขั้นตอนใดในแผนภาพหลัก
