# คำอธิบาย Use Case Diagram
## StaySense Phitsanulok: Accommodation Search System Using Semantic Search Techniques

ไฟล์ที่เกี่ยวข้อง:
- โค้ดแผนภาพ (แก้ไขต่อได้): `staysense-usecase.mmd`
- ภาพประกอบการนำเสนอ: `staysense-usecase.svg`, `staysense-usecase.png`
- ตารางความสัมพันธ์ (สร้างอัตโนมัติจากโค้ดแผนภาพ): `relationship_table.md`

> **หมายเหตุสำคัญเรื่องขนาดภาพ**: ระบบนี้มี Use Case ทั้งหมด 82 รายการ และความสัมพันธ์ 105 เส้น ซึ่งมากกว่าปกติมากสำหรับ Use Case Diagram หนึ่งภาพ (ตามข้อกำหนดข้อ 7 ที่ต้องรวมทุกอย่างไว้ภาพเดียว) ผลคือภาพมีขนาดใหญ่และมีเส้นจำนวนมาก แม้จะจัดกลุ่มด้วยสีและ Subgraph แล้วก็ตาม **หากต้องการนำไปใส่ในเล่มวิจัยจริง แนะนำให้แจ้งเพื่อแบ่งเป็นหลายภาพย่อยตามกลุ่ม Actor** (เช่น ภาพผู้เยี่ยมชม/สมาชิก, ภาพผู้ดูแลระบบ) เช่นเดียวกับที่ทำกับ Workflow Diagram ก่อนหน้านี้ — ภาพเดียวนี้เหมาะสำหรับใช้เป็นเอกสารอ้างอิงฉบับสมบูรณ์ (Master Reference) มากกว่าภาพที่จะพิมพ์ลงหน้ากระดาษเดียว

## 1. ขอบเขตของระบบ

ระบบ StaySense Phitsanulok ครอบคลุมที่พัก 3 ประเภท (โรงแรม รีสอร์ต โฮมสเตย์) ใน 9 อำเภอของจังหวัดพิษณุโลก โดยไม่มีผู้ใช้งานประเภทเจ้าของที่พัก และไม่มีฟังก์ชันการจองหรือชำระเงิน — ตรวจสอบแล้วว่าแผนภาพนี้ไม่มี Accommodation Owner, Booking, Payment หรือ Approve Booking ปรากฏอยู่

## 2. คำอธิบาย Actor

| Actor | คำอธิบาย |
|---|---|
| **🧍 Guest** (ผู้เยี่ยมชม) | ผู้ใช้งานที่เข้าเว็บไซต์โดยไม่ต้องเข้าสู่ระบบ ค้นหาและเรียกดูข้อมูลที่พักได้ผ่าน Use Case หลัก `Search Accommodations` รวมถึง `Register` และ `Login` เพื่อสมัครสมาชิก |
| **🧑‍💼 Registered User** (สมาชิก) | สืบทอดความสามารถทั้งหมดของ Guest ผ่านความสัมพันธ์ Generalization และมีฟังก์ชันเฉพาะบุคคลเพิ่มเติม เช่น รายการโปรด ประวัติการค้นหา การเปรียบเทียบ และคำแนะนำเฉพาะบุคคล |
| **🛠️ Administrator** (ผู้ดูแลระบบ) | รับผิดชอบบริหารจัดการข้อมูลที่พัก ข้อมูลอ้างอิง (ประเภทที่พัก ประเภทห้อง สิ่งอำนวยความสะดวก รูปภาพ ตำแหน่ง สถานที่ใกล้เคียง แหล่งข้อมูล) ข้อมูลผู้ใช้งาน และการปรับปรุงดัชนีข้อมูลสำหรับ Semantic Search ต้องผ่าน `Authenticate Administrator` ก่อนใช้งานทุกฟังก์ชันหลัก |
| **🗺️ Google Maps Service** (ระบบภายนอก) | บริการแผนที่ภายนอกที่ระบบเรียกใช้สำหรับตำแหน่งปัจจุบัน การแสดงแผนที่ และการจัดการพิกัด/สถานที่ใกล้เคียง แสดงด้วยกรอบเส้นประเพื่อระบุว่าเป็นระบบภายนอก ไม่ใช่ผู้ใช้งานของระบบ |

## 3. คำอธิบาย Use Case แบ่งตามกลุ่ม

### 3.1 Search and Browsing Functions (สีฟ้า) — 13 Use Case
ฟังก์ชันการค้นหาและเรียกดูข้อมูลที่พักซึ่งผู้เยี่ยมชมใช้งานได้ทันทีโดยไม่ต้องเข้าสู่ระบบ ประกอบด้วยการสมัครสมาชิก/เข้าสู่ระบบ, การค้นหาหลัก (`Search Accommodations`) พร้อมเงื่อนไขทางเลือก (ประเภท, อำเภอ, ตัวกรอง, ตำแหน่งปัจจุบัน), การดูผลลัพธ์และรายละเอียดที่พัก, การดูแผนที่, สถานที่ใกล้เคียง และการแบ่งปันข้อมูล

### 3.2 Semantic Search Functions (สีม่วงอ่อน) — 8 Use Case
กระบวนการภายในที่ถูกเรียกใช้ทุกครั้งที่มีการค้นหา ได้แก่ การเตรียมคำค้นหา (`Process Search Query`, `Preprocess Query`) และแกนหลักของเทคนิคการค้นหาเชิงความหมาย (`Semantic Search`) ซึ่งประกอบด้วยการแปลงคำค้นหาเป็นเวกเตอร์ การเรียกเวกเตอร์ที่พักที่จัดเก็บไว้ การคำนวณความคล้ายคลึง การกรองตามเงื่อนไข และการจัดลำดับผลลัพธ์

### 3.3 Authentication and Authorization (สีเหลือง) — 2 Use Case
`Authenticate User` สำหรับตรวจสอบสิทธิ์สมาชิกก่อนใช้ฟังก์ชันส่วนบุคคลทุกรายการ และ `Authenticate Administrator` สำหรับตรวจสอบสิทธิ์ผู้ดูแลระบบก่อนเข้าใช้งานฟังก์ชันบริหารจัดการหลัก

### 3.4 Member Functions (สีเขียวอ่อน) — 17 Use Case
ฟังก์ชันเฉพาะสมาชิก ได้แก่ การจัดการโปรไฟล์, รายการโปรด (เพิ่ม/ดู/ลบ), ประวัติการค้นหาและที่พักที่เปิดดูล่าสุด (รวมถึงการบันทึกอัตโนมัติ `Record Search History` และ `Record Recently Viewed`), การเปรียบเทียบที่พัก (พร้อม Use Case ย่อยสำหรับเลือกรายการและแสดงผลเปรียบเทียบ), คำแนะนำเฉพาะบุคคล (พร้อม Use Case ย่อยสำหรับดึงข้อมูลความชอบ ประวัติ และสร้างคำแนะนำ) และการออกจากระบบ

### 3.5 Administration Functions (สีส้มอ่อน) — 42 Use Case
ฟังก์ชันบริหารจัดการของผู้ดูแลระบบ แบ่งเป็นกลุ่มย่อยตาม Package ดังนี้:
- **Manage Accommodations** — CRUD ข้อมูลที่พักหลัก พร้อมการตรวจสอบข้อมูล บันทึกแหล่งที่มา และปรับปรุงข้อมูลสำหรับ Semantic Search
- **Manage Accommodation Types / Room Types / Amenities** — ข้อมูลอ้างอิงพื้นฐาน
- **Manage Accommodation Images / Manage Room Images** — จัดการรูปภาพที่พักและรูปภาพห้องพัก พร้อม Use Case ย่อยสำหรับอัปโหลด แสดงตัวอย่าง กำหนดรูปปก จัดลำดับ และลบ
- **Manage Locations and Coordinates / Manage Nearby Places** — ตำแหน่งพิกัดและสถานที่สำคัญใกล้เคียง
- **Manage Accommodation Sources** — บันทึกและตรวจสอบแหล่งที่มาของข้อมูล
- **Manage Users and Roles** — ข้อมูลผู้ใช้งานและสิทธิ์การเข้าถึง
- **Update Semantic Search Data** — เตรียมข้อความ แปลงเป็นเวกเตอร์ บันทึก/ปรับปรุง หรือปิดใช้งานเวกเตอร์ของที่พัก

## 4. คำอธิบายความสัมพันธ์

| ประเภท | สัญลักษณ์ในแผนภาพ | ความหมาย | ตัวอย่าง |
|---|---|---|---|
| **Association** | เส้นทึบไม่มีหัวลูกศร | Actor ใช้งาน Use Case นั้นโดยตรง | Guest — Search Accommodations |
| **Generalization** | เส้นทึบหนาพร้อมหัวลูกศร (แทนหัวลูกศรสามเหลี่ยมโปร่งที่ Mermaid Flowchart ไม่รองรับโดยตรง) | Actor หนึ่งสืบทอดความสามารถทั้งหมดของอีก Actor หนึ่ง | Registered User → Guest |
| **«include»** | เส้นประพร้อมหัวลูกศร ชี้จาก Use Case หลักไปยัง Use Case ที่ถูกเรียกใช้ | Use Case หลักต้องเรียกใช้ Use Case ปลายทางทุกครั้งที่ทำงาน | Search Accommodations «include» Semantic Search |
| **«extend»** | เส้นประพร้อมหัวลูกศร ชี้จาก Use Case เสริมไปยัง Use Case หลัก | Use Case ต้นทางเป็นทางเลือกเสริมที่เกิดขึ้นตามเงื่อนไข ไม่บังคับทุกครั้ง | Select Accommodation Type «extend» Search Accommodations |

**หลักการเลือกใช้ที่ยึดตามในแผนภาพนี้**: ฟังก์ชันที่ทำงานทุกครั้งโดยไม่มีเงื่อนไข (เช่น กระบวนการค้นหาเชิงความหมาย การตรวจสอบสิทธิ์) ใช้ `«include»` ส่วนฟังก์ชันที่ผู้ใช้งานเลือกใช้ตามความต้องการหรือเกิดขึ้นเฉพาะบางเงื่อนไข (เช่น ตัวกรองการค้นหา การอัปโหลดรูปภาพย่อย การยืนยันการลบ) ใช้ `«extend»`

## 6. การตรวจสอบตามข้อกำหนด

- ✅ ไม่มี Accommodation Owner / Dormitory Owner, Booking, Confirm Booking, Payment, Approve Booking ในแผนภาพ
- ✅ ข้อความในแผนภาพเป็นภาษาอังกฤษทั้งหมด
- ✅ ใช้ `«include»` เฉพาะกรณีเรียกใช้บังคับทุกครั้ง และ `«extend»` เฉพาะกรณีเสริม/มีเงื่อนไข ตามหลัก UML
- ✅ Registered User สืบทอดจาก Guest ด้วย Generalization
- ⚠️ เนื่องจาก Mermaid ไม่รองรับสัญลักษณ์ Use Case Diagram โดยตรง (ไม่มีรูปคนแบบ Stick Figure หรือหัวลูกศรสามเหลี่ยมโปร่งจริง) จึงจำลองด้วย Flowchart Syntax: Actor = สี่เหลี่ยมพร้อมอีโมจิแทนสัญลักษณ์บุคคล, Use Case = กรอบ Stadium (ปลายมน คล้ายวงรี), Generalization = เส้นหนาแทนหัวลูกศรสามเหลี่ยมโปร่ง
