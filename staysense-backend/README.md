# StaySense Phitsanulok — FastAPI Backend

Backend for the StaySense Phitsanulok Vue frontend: accommodation CRUD,
filtering, favorites, auth, and semantic search (Sentence Transformers +
FAISS) over a MySQL database.

## Quick start

```bash
# 1. MySQL (via Docker — or point DATABASE_URL at your own instance)
docker compose up -d

# 2. Python env
python -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt

# 3. Config
cp .env.example .env
# edit .env if your MySQL credentials differ from the docker-compose defaults

# 4. Apply the schema addenda.
#    - Fresh `docker compose up` runs schema.sql + every schema_addendum_*.sql
#      automatically (they're mounted into /docker-entrypoint-initdb.d).
#    - For a DB that already exists (Docker volume kept, or your own MySQL),
#      apply the addenda through the app's own DB connection — no mysql CLI
#      needed, handles the DELIMITER trigger blocks, safe to re-run:
python apply_addenda.py
#      (or target one file:  python apply_addenda.py schema_addendum_4.sql)

# 5. Seed demo data (same mock hotels the frontend used to hardcode)
python seed_accommodations.py
python seed_places.py            # Phitsanulok points of interest for the detail page's nearby rail

# 6. Run the API
uvicorn app.main:app --reload --port 8000
```

API docs: http://localhost:8000/docs (Swagger UI, auto-generated by FastAPI)

## Connecting the Vue frontend

In the `staysense-vue` project, replace the two mock modules with real API
calls — everything else (components, computed filters, the whole UI) stays
the same because the response shapes match exactly:

**`src/data/mockHotels.js`** — replace `generateHotels()`:
```js
export async function fetchHotels(params = {}) {
  const qs = new URLSearchParams(params)
  const res = await fetch(`http://localhost:8000/api/accommodations?${qs}`)
  const data = await res.json()
  return data.items // same shape as generateHotels()'s return value
}
```

**`src/composables/useSemanticSearch.js`** — replace `runSemanticSearch()`:
```js
export async function runSemanticSearch(query) {
  if (!query.trim()) return null
  const res = await fetch('http://localhost:8000/api/search', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ query }),
  })
  const data = await res.json()
  const scores = new Map(data.items.map((item, i) => [item.id, data.items.length - i]))
  return { scores, priceCeiling: data.meta.priceCeiling, terms: data.meta.terms }
}
```

`HotelsView.vue` and `HomeView.vue` will need small `async`/`await` tweaks
around these two calls (they're currently synchronous), but no component
templates or filter logic need to change.

Also set `CORS_ORIGINS` in `.env` to match wherever `npm run dev` serves the
frontend (defaults to `http://localhost:5173`).

## API overview

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/accommodations` | – | List with filters: `type`, `district` (repeatable), `price_min`, `price_max`, `rating_min`, `amenities` (repeatable), `distance_max_km`, `sort`, `page`, `page_size` |
| GET | `/api/accommodations/{id}` | – | Detail |
| POST | `/api/accommodations` | admin | Create |
| PUT | `/api/accommodations/{id}` | admin | Update |
| DELETE | `/api/accommodations/{id}` | admin | Delete |
| GET | `/api/districts` | – | List all 9 districts |
| GET | `/api/districts/counts` | – | Counts per district for the current filters (feeds `DistrictMap.vue`) |
| GET | `/api/amenities` | – | Amenity list |
| GET | `/api/accommodation-types` | – | Type list |
| POST | `/api/search` | – | Semantic search: `{ query, type?, page?, page_size? }` |
| POST | `/api/search/reindex` | admin | Rebuild the FAISS index after bulk data changes |
| POST | `/api/auth/register` | – | Sign up |
| POST | `/api/auth/login` | – | Sign in, returns JWT |
| GET | `/api/auth/me` | user | Current user |
| GET | `/api/favorites` | user | List favorites (each item has `fav: true`) |
| POST /DELETE | `/api/favorites/{id}` | user | Add / remove a favorite |

All accommodation responses share one shape (`AccommodationOut` in
`app/schemas.py`) matching `src/data/mockHotels.js` field-for-field:
`id, name, district, type, price, rating, reviews, distanceKm, landmark,
amenities, tags, reason, img, fav`.

## Semantic search notes

- `app/semantic/embedder.py` lazily loads the model named in
  `EMBEDDING_MODEL_NAME` (default `intfloat/multilingual-e5-small`, per the
  earlier architecture discussion). The model downloads from Hugging Face
  on first use — make sure the machine running this has internet access at
  least once (it's cached locally after that).
- `app/semantic/index.py` builds an in-memory FAISS `IndexFlatIP` (cosine
  similarity) from each accommodation's name + description + tags +
  district + landmark. It's rebuilt automatically at startup and after any
  create/update/delete through the admin endpoints; call
  `POST /api/search/reindex` manually after bulk SQL changes.
- The price-ceiling extraction (`extract_price_ceiling`) mirrors the
  frontend's regex-based approach from `useSemanticSearch.js`, so behavior
  is consistent whether or not the real backend is wired up yet.
- If the embedding model can't load (no internet, first run), the API
  still starts — `/api/search` just returns an empty result set until
  `/api/search/reindex` succeeds.

## Files

```
app/
  main.py            — FastAPI app, CORS, router registration, startup indexing
  config.py          — env-based settings (pydantic-settings)
  database.py        — SQLAlchemy engine/session
  models.py          — ORM models (mirrors schema.sql + schema_addendum.sql)
  schemas.py          — Pydantic request/response models
  crud.py             — query builders (filtering, sorting, district counts)
  auth.py             — password hashing + JWT
  semantic/
    embedder.py        — Sentence Transformers wrapper (lazy-loaded)
    index.py            — FAISS index build/search + price-ceiling extraction
  routers/
    accommodations.py, districts.py, reference.py, search.py, auth.py, favorites.py
schema.sql            — from the earlier MySQL design (districts, types, amenities, etc.)
schema_addendum.sql    — adds accommodations.tags_json (frontend pill tags)
schema_addendum_2.sql  — expands the amenities reference set (6 -> 16 codes)
schema_addendum_3.sql  — room_types table, policy fields, per-category rating averages + triggers
schema_addendum_4.sql  — richer room_types: standard occupancy, extra-bed price, bedrooms/bathrooms/units (per-house detail)
schema_addendum_5.sql  — pricing conditions (deposit amount/%, advance booking), contact channels (LINE/FB/IG/web), google_maps_url
schema_addendum_6.sql  — places table (points of interest); GET /api/accommodations/{id}/nearby computes distances live (haversine)
schema_addendum_7.sql  — room_types: view_type, room_amenities_json, extra_bed_max, per-room rules + room_type_images (photos per room)
schema_addendum_8.sql  — trims accommodation_types to 3 (โรงแรม / รีสอร์ต / โฮมสเตย์); drops hostel + guesthouse
seed_places.py         — ~30 real Phitsanulok POIs (temples, stations, malls, hospitals, markets…) with coordinates
apply_addenda.py       — applies schema_addendum_*.sql to an already-running DB via SQLAlchemy (no mysql CLI); idempotent
seed_accommodations.py — reproduces the frontend's old mock hotel dataset in real MySQL rows (now also seeds/backfills room types)
docker-compose.yml     — local MySQL for development
```
